# Fake News Detection System

## 1. Project overview

This local web application demonstrates binary news-text classification with a machine-learning model trained on the supplied `Fake.csv` and `True.csv` files. It predicts whether text resembles the dataset's **Fake** or **Real** examples.

This is an academic machine-learning demonstration, not a fact-checking service. Its output is a learned classification, not proof that a claim is true or false.

## 2. Problem statement

News readers encounter articles with very different writing patterns. This project applies text classification to learn patterns associated with two labeled groups in a provided dataset and makes the trained model available through a simple web page.

## 3. Project objectives

- Inspect and clean the supplied data without inventing labels.
- Combine the title and article text, and remove fields that could leak class information.
- Train a TF-IDF and Logistic Regression pipeline without fitting text features on the test set.
- Evaluate on held-out examples and save the report.
- Provide a responsive local interface for trying the saved model.

## 4. Application features

- Paste a headline or article and request a Fake/Real class prediction.
- Client and server validation, loading feedback, clear/reset, and helpful errors.
- A model information panel showing holdout metrics and dataset counts after training.
- Local model inference; the application does not send submitted text to an external prediction service.
- A saved confusion-matrix image and JSON evaluation report.

## 5. Technologies and libraries

- **Python** structures the training and web application code.
- **pandas** reads and cleans the CSV datasets.
- **NumPy** supports numeric machine-learning operations.
- **scikit-learn** provides TF-IDF, Logistic Regression, data splitting, and evaluation.
- **joblib** saves and loads the complete fitted scikit-learn pipeline.
- **Flask** serves the HTML page and prediction/information endpoints.
- **Matplotlib** writes the confusion-matrix visualization.
- **HTML, CSS, and JavaScript** implement the accessible, responsive page and its API interactions.

## 6. Dataset description

The supplied files are in `data/`:

| File | Rows inspected | Columns | Label assigned |
| --- | ---: | --- | --- |
| `Fake.csv` | 23,481 | `title`, `text`, `subject`, `date` | `0` (Fake) |
| `True.csv` | 21,417 | `title`, `text`, `subject`, `date` | `1` (Real) |

There are 44,898 source rows. Inspection found 630 blank/missing `text` values in `Fake.csv` and 1 in `True.csv`; titles are joined with article text, so these rows are retained when their title is present. After combining and normalizing title and body, 5,798 repeated article texts are removed. The repeated texts had no label conflicts. The final dataset contains 39,100 rows: 17,905 Fake and 21,195 Real. These counts are written to `evaluation/metrics.json` by training and displayed by the application.

`subject` and `date` are intentionally excluded. Subject categories can strongly correlate with the source label and may let a model learn dataset/source artifacts rather than article language. The class label is added from the filename; no label column is assumed in the source files.

## 8. System architecture

1. `train_model.py` loads both CSV files, assigns labels by filename, cleans/combines title and body, and removes duplicate normalized text.
2. It shuffles and splits the examples into stratified training and test sets.
3. A single scikit-learn pipeline learns TF-IDF vocabulary/weights from training text and fits Logistic Regression.
4. The script evaluates the holdout set and writes one serialized pipeline plus JSON and PNG evaluation artifacts.
5. `app.py` loads the saved pipeline once when the Flask process starts.
6. The browser sends text to `POST /api/predict`; Flask returns the predicted class. `GET /api/info` supplies saved metrics and dataset details to the page.

## 9. Text preprocessing and data cleaning

- The class is assigned as `0` for rows from `Fake.csv` and `1` for rows from `True.csv`.
- Missing title/body cells are treated as empty strings; title and body are joined with a space, preserving a usable title when the body is blank.
- Repeated whitespace is collapsed and surrounding whitespace removed.
- Rows with no combined title/body are removed.
- Duplicate detection is case-insensitive and whitespace-normalized on the combined text. If identical normalized text has different labels, training stops with an error instead of choosing a label arbitrarily.
- `subject` and `date` are excluded from the training frame.
- TF-IDF lowercases and strips Unicode accents, ignores common English stop words, and represents both single words and adjacent two-word sequences.

No stemming or lemmatization is applied. The vectorizer and classifier are fitted together inside a pipeline, and the pipeline is fitted only on the training partition.

## 10. TF-IDF

TF-IDF means **Term Frequency–Inverse Document Frequency**. Term frequency reflects how often a word or phrase appears in one article; inverse document frequency reduces the influence of terms that occur in nearly every article. The resulting sparse numeric features let a traditional classifier learn which words and two-word phrases are useful in the training examples.

## 11. Selected algorithm

The classifier is **Logistic Regression**. Despite its name, it is used for classification: it learns weights for text features and uses them to choose one of the two classes. It is a practical baseline for sparse TF-IDF text data, trains locally, and is relatively straightforward to explain.

## 12. Training and testing split

Training uses an 80% training / 20% test split with `random_state=42`. Stratification preserves the class proportions in each partition. The test partition is kept out of vectorizer/classifier fitting and is used for the reported evaluation.

## 13. Evaluation metrics and actual results

Run training to create `evaluation/metrics.json` and `evaluation/confusion_matrix.png`. The JSON file includes accuracy, Real-class precision/recall/F1, a per-class classification report, and the confusion matrix. The application displays the four summary metrics.

Training was run with `random_state=42` and an 80/20 stratified split. The held-out test set has 7,820 rows (3,581 Fake and 4,239 Real).

| Metric | Result |
| --- | ---: |
| Accuracy | 99.10% |
| Precision (Real class) | 98.76% |
| Recall (Real class) | 99.60% |
| F1 score (Real class) | 99.18% |

Per-class test-set report:

| Class | Precision | Recall | F1 score | Support |
| --- | ---: | ---: | ---: | ---: |
| Fake | 99.52% | 98.52% | 99.02% | 3,581 |
| Real | 98.76% | 99.60% | 99.18% | 4,239 |

Confusion matrix (rows are actual Fake/Real; columns are predicted Fake/Real):

| Actual \ Predicted | Fake | Real |
| --- | ---: | ---: |
| Fake | 3,528 | 53 |
| Real | 17 | 4,222 |

These results describe only the held-out examples from this dataset; they do not establish real-world accuracy or truthfulness. See `evaluation/metrics.json` for full precision values and the complete classification report, and `evaluation/confusion_matrix.png` for the plot.

Metric interpretation:

- **Accuracy:** fraction of test examples classified correctly.
- **Precision (Real):** among examples predicted Real, fraction whose dataset label is Real.
- **Recall (Real):** among test examples labeled Real, fraction identified as Real.
- **F1 score (Real):** harmonic mean of Real-class precision and recall.
- **Confusion matrix:** counts of actual versus predicted Fake/Real labels; inspect it to see which class errors occur.

## 14. Saving and loading the model

Training serializes the whole fitted scikit-learn pipeline to `models/fake_news_pipeline.joblib`. That pipeline contains both the learned TF-IDF vectorizer and Logistic Regression classifier. Flask loads it once at startup, so application launches do not retrain the model. Retrain after changing the dataset or training code.

## 15. Flask and the model

`GET /` renders the page. `POST /api/predict` validates JSON input and calls `predict()` on the saved pipeline. `GET /api/info` returns the metrics and dataset summary generated during training. If no model exists, predictions return a clear instruction to train it; model-load errors are surfaced in the server console rather than exposing stack traces in the page.

## 16. Frontend

- **HTML** defines the input, result, process explanation, and model summary.
- **CSS** provides responsive desktop/mobile layouts, cards, status colors, and loading animation.
- **JavaScript** validates input, calls the Flask JSON endpoints, handles errors and loading state, and populates metrics.

The interface does not display a probability/confidence score. The model is not calibrated for confidence, and a probability-like score should not be mistaken for the chance that a claim is true.

## 20. Open and test the application

Open `http://127.0.0.1:5000` in a browser. Paste a headline/article and select **Check this story**. Try a short headline and a longer passage; the output is a model class, not a fact-check. Use **Clear text** to reset the form.

## 21. Common errors

- **Dataset file not found:** confirm both CSVs are in `<project>\data\` and named exactly `Fake.csv` and `True.csv`.
- **Missing columns:** ensure each file includes `title`, `text`, `subject`, and `date`; investigate a different delimiter/encoding if the header is read as one column.
- **Conflicting duplicate labels:** identical normalized title/body text appears in both classes. Inspect the conflicting rows and correct the source labels before training.
- **Module not found:** activate `.venv` and run `pip install -r requirements.txt`.
- **Model has not been trained:** run `python train_model.py`, then stop and restart `python app.py`.
- **Port 5000 is busy:** stop the other local service using that port, then launch again.
- **PowerShell activation blocked:** use the process-scoped execution-policy command in section 18.

## 22. Limitations and future improvements

- Dataset-specific language, source composition, and time period can influence the learned patterns.
- This binary classifier cannot verify sources, inspect external evidence, or establish whether a claim is true.
- New topics, writing styles, and distribution changes may reduce performance.
- The interface deliberately does not present uncalibrated probabilities as confidence.
- Possible extensions include evaluating on a separately sourced dataset, adding calibration after validation, improving interpretability, and comparing additional models.

## 23. Conclusion

The project demonstrates a complete local text-classification workflow: data inspection and cleaning, leakage-aware TF-IDF model training, holdout evaluation, model persistence, Flask inference, and a responsive web interface. Results should be interpreted as dataset classification performance rather than real-world fact verification.

## 24. Viva questions and answers

**Q: Why do the CSV files not need a label column?**  
A: The source file identity supplies the label: `Fake.csv` maps to 0 and `True.csv` maps to 1.

**Q: Why combine title and article text?**  
A: Both carry useful language. Combining them lets the classifier use the headline and body in one input.

**Q: Why remove subject and date?**  
A: Subject can correlate strongly with the label and cause source/topic leakage; date is metadata rather than article language. Removing both focuses the model on title and body text.

**Q: What does TF-IDF do?**  
A: It represents text as numeric word/phrase weights, emphasizing terms that are useful in an article but not common across all articles.

**Q: Why Logistic Regression?**  
A: It is an efficient, interpretable baseline for sparse text features and supports binary classification.

**Q: Why split into training and test data?**  
A: Training data is used to learn the vocabulary and classifier weights. Separate test data estimates performance on examples not used during fitting.

**Q: Why stratify the split?**  
A: Stratification keeps similar Fake/Real proportions in training and testing sets.

**Q: What is data leakage, and how is it avoided?**  
A: Leakage is information from held-out examples influencing training. The vectorizer is inside a scikit-learn pipeline and is fitted only when the training partition is fit.

**Q: Does high accuracy prove an article is real?**  
A: No. Metrics describe agreement with dataset labels on a specific held-out sample. They do not verify real-world claims.

**Q: What do precision, recall, and F1 measure?**  
A: Precision measures correctness among positive predictions; recall measures how many actual positives were found; F1 balances the two. Here, the positive class is Real.

**Q: What is the confusion matrix?**  
A: It counts correct and incorrect predictions for each actual/predicted class pair.

**Q: Why save the pipeline?**  
A: It persists the learned vectorizer and classifier together, ensuring prediction uses the same text representation without retraining on each launch.

**Q: What role does Flask play?**  
A: Flask serves the web page and provides JSON endpoints that connect browser input with the saved model.

**Q: Is the displayed result a calibrated confidence?**  
A: No confidence score is displayed. The output is only the predicted class because uncalibrated model probabilities can be misleading.
